Prayer Times Desktop v3.0.6
Built on v3.0.5. English and Bangla throughout.

- A: "Mark as read" / "পড়েছি" under the A Blessed Reminder passage (beside Read more / Full section / Today's portion). Only this button counts a passage as read. Then "Read ✓" / "পড়া হয়েছে ✓" and the next unread passage; all read: "Today's portion read ✓" / "আজকের অংশ পড়া শেষ ✓".
- B: every passage in Today's portion has Mark as read or "Undo read" / "পড়া চিহ্ন সরান"; undo affects only that passage.
- C: "N of M passages read today" counts confirmed passages only; M includes featured passages. The old automatic counts (key prayer-times-blessed-reading) are cleared.
- D: lunar-year plan (src/reading-plan.js): 2,739 passages / 6,236 verses in mushaf order over the Hijri year (354 or 355 days), breaks only between passages, day d ends at the passage boundary nearest d x 6,236 / days verses; 354 days: 14-23 verses and 3-15 passages a day (average 17.6 and 7.7); 355 days: 13-21 verses and 2-15 passages. Deterministic. Juz' label = juz' of today's passages.
- E: featured passages with sources: 9 Dhul Hijjah 5:3-4 (Bukhari 45, Muslim 3017); 17 Ramadan 8:41-44 (Badr; Ibn Ishaq; labelled approximate); 27 Ramadan 96:1-5 (labelled commonly held; Bukhari 3, Muslim 762). Shown first with a one-line note; plan unchanged; read mark shared with the same passage.
- F: read marks per passage per Hijri year (key prayer-times-reading-plan, one bit per passage); today's portion never grows; "X passages behind this year" lists earlier unread passages oldest first; a new year starts a fresh plan, older years kept (Settings shows a line per year); backup export, replace and merge carry them (backup key "reading").
- G: reading day = civil date at midnight in the time zone of the saved location (offline lookup, @photostructure/tz-lookup 11.8.0, CC0).
- H: Hijri date by location from moon-sighting 1.2.0 (MIT, Aric Camarata) with the Odeh criterion (zones A-C = visible by eye or optical aid): crescent visible on the evening of the 29th -> month starts at that sunset, else 30 days; one chain per location from Muharram 1440. Day still changes at Maghrib; -2..+2 adjustment on top; label "Predicted by crescent visibility" / "নতুন চাঁদ দেখা যাওয়ার পূর্বাভাস অনুযায়ী". Fallback to Umm al-Qura (no label) without a location, beyond the polar circles (|latitude| > 66.56, where some days have no sunset and the chain drifts away from the moon) or outside 1440 AH-2150 CE. The polar limit is stated in Settings > About in English and Bangla.
- I: offline only. The library is bundled as src/vendor/moon-sighting.js generated by scripts/vendor-libs.mjs with its telemetry ping and kernel-download code removed; the only network call in the app is reading its own bundled kernel file (same origin).
- J: privacy text unchanged; moon-sighting MIT licence, DE442S notice and tz-lookup CC0 added to LICENSES, About and src/vendor/LICENSES-v3.0.6.txt.
- K: version 3.0.6 (label v3.0.6 / v৩.০.৬).
- L: JPL DE442S kernel bundled at public/ephemeris/de442s.bsp (32,701,440 bytes, MD5 cc49327e06088124c0e39d8dde9f0b58 as published by NAIF; the file was downloaded from a public mirror because naif.jpl.nasa.gov did not connect from the build machine, and its MD5 was checked against NAIF's own aa_checksums.txt). The app reads it before its first screen but never waits more than 15 s; if it stalls, the app starts with the Umm al-Qura date until the file has been read.
- M: astrolabe and Sun/Moon cards use DE442S positions, phase, illumination, moonrise/moonset, heights and directions (src/moon-engine.js); astrolabe files and look unchanged.
- The “I no internet” unit test now walks and compares source paths with Node’s path module, so it passes on Windows as well as Linux. App code unchanged.
